# Phase 16 · 全站文案规范

这份规范约束应用里**所有用户能看到的字**：页面标题、按钮、说明、空状态、错误、toast、对话框、表格表头、表单标签、aria-label 与 placeholder。
它不约束学习材料（单词释义、例句、阅读原文、考试题干）——那些是内容，不是界面文案。

## 一、语气

- **像一个懂行的朋友在说话**，不像系统在通知你。主语尽量是「你」和「这件事」，不用「系统」「模块」「引擎」。
- **短句**。一句话只说一件事；能用一句话说完就不要用两句；能用动词就不要用名词化的抽象词（「保存」>「持久化」「写入存储」）。
- **横幅一致**：同一个东西，全站只有一个名字（见术语表）。中英不混用：标题、按钮、说明全中文；只有单词本身、产品名「词间」、以及用户自己填的 API 名称可以是英文。
- **不解释实现**。用户在界面上不需要知道「队列」「预算收敛」「能力门控」「证据等级」。要说的是**他能做什么、做完会怎样**。
- **不打包票**。涉及记忆与分数的表述必须保留边界（「估算」「不保证」「答对一次不算掌握」），但用日常说法，不用统计学术语。
- **不用感叹号堆情绪**，不用「！」，不用「哦」「啦」。删掉「请」「务必」这类公文措辞，除非是真的不可逆操作。

## 三、句式规则

1. **页面标题**：一句人话，说这一页替你解决什么。不用名词堆（「学习统计」可以，「记忆洞察 · MEMORY INSIGHTS」不行）。
2. **副标题**：一句补充，说清「数据从哪来 / 边界在哪」，不重复标题。
3. **按钮**：动词开头，说**结果**（「生成今天的计划」，不是「提交」）；禁用态在旁边的说明里写清为什么不能用。
4. **说明文字**：先结论，后条件。一段最多两句。
5. **空状态**：说清现在没有什么 + 下一步做什么（「还没有词。先导入一本词书」）。
6. **错误**：发生了什么 + 数据是否受影响 + 下一步。不用「异常」「失败」单独收尾。
7. **数字**：带单位的写单位（「12 个词」「0.13 秒」）；百分比保留一位小数；不确定的数用「约」。
8. **英文残留**：界面不再出现全大写英文小标题；确需英文（如 API、CORS、token）保持原样但同一处只出现一次，并紧跟中文解释。

| 禁用 | 替换 |

| 队列 | 这一轮 |
| 词池 | 词库来源 / 具体来源名 |
| 预算 | 可用时间 |
| 隔夜检测 | 昨天学的还记得吗 |
| 保留率 | 还记得多少 |
| 有效掌握 | 稳定记住 |
| 识别 / 提取 / 产出（作为能力名） | 看得懂 / 想得起 / 用得出 |
| 编码 | 第一印象 |
| Recall / Preview | 回忆测试 / 预览 |
| 生命周期 | 学习阶段 |
| 反应时间 | 用时 |

## 五、验收口径

- 静态：`scripts/phase16-forbidden-scan.mjs` 扫描界面源码，禁用词 0 命中；全大写英文小标题 0 命中。
- 动态：`scripts/phase16-capture-copy.mjs` 抓 20 个界面状态的所有文字，同样 0 命中；页面标题、按钮、空状态、错误逐条过一遍。
- 边界不删：涉及「不保证」「估算」「答对一次不算掌握」的表述必须保留，只能改写措辞。
- 生产构建：`scripts/phase16-prod-accept.mjs` 走真实导入 + 真实训练，14 个入口 × 3 宽度 × 2 主题，同时检查可见文案、属性文案、横向溢出与控制台报错。

## 六、容易漏的几类

1. **数字与符号**：说明句里不要出现 `=`（「底条长度 = 分钟数」改成「条越长，占的时间越多」）。单位全站统一中文：`分钟`、`秒`、`个`、`篇`、`次`；不再出现 `5′`、`0.16 s`。
2. **中英双轨**：同一个概念只给中文，不要「中文 · English」并排（推荐理由徽标、页面小标题都曾这样）。
3. **属性里的文案**：`aria-label`、`placeholder`、`title` 与可见文案同等对待，`placeholder` 里的英文示例（`Start with one simple sentence...`）也要改。
4. **开发遗留**：原型切换器、调试按钮、版本号、内部自检结果（`图谱自检 · taxonomyVersion`）不应出现在产品界面；保留能力时按 URL 参数或环境变量隐藏。
5. **改文案会挪布局**：按钮变长会被裁切（`上传文件 选择 TXT / MD / HTML` 就被截断）。改完必须回头看截图与溢出测量，不能只改字符串。
