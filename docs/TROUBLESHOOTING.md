# 故障排查（长期使用 / 数据安全）

## 1. 打开后看不到原来的词

先确认地址。浏览器按 origin 隔离：

| 你之前用的地址 | 数据是否在 `localhost:4173` |
| --- | --- |
| `http://localhost:4173` | 是 |
| `http://127.0.0.1:4173` | **否** |
| `http://localhost:4174` | **否** |
| 另一个浏览器 / 无痕窗口 | **否** |

不要在未备份时清空任何一个地址。处理顺序：

1. 回到你**之前实际使用**的地址；
2. 设置 → 导出全部学习数据；
3. 到推荐地址导入；
4. 核对词书/单词/记录数量；
5. 确认无误前保留旧地址和备份。

更多见 `docs/ORIGIN_DATA_SAFETY.md`。

## 2. 导入备份失败 / 提示结构无效

- 应用先校验再替换；校验失败时现有数据不会改动。
- 不要反复点“确认替换”，不要清空当前数据。
- 保留原 JSON；检查它是否来自正确的应用、是否被手工改坏、版本是否高于当前。
- 旧版本缺少可选域时，应用会补空后恢复；核心引用损坏则拒绝。

## 3. 导入中途出错

Phase 14 起，`replaceData` 遇到无法写入的项会 `tx.abort()` 回滚整个事务，不会留下半套数据。若仍看到异常：

1. 刷新页面，导出当前数据做第二份备份；
2. 检查浏览器存储空间（设置 → 申请持久存储）；
3. 换一个空白浏览器 profile 试导入，判断是数据问题还是当前 profile 问题；
4. 不要把唯一备份覆盖掉。

## 4. 更新后仍是旧页面

- 正常关闭所有应用标签页再打开；PWA 新版本会 `skipWaiting` + `clients.claim`。
- 若仍是旧资源，检查 `dist/sw.js` 的缓存名是否带构建指纹（`erv2-shell-v2-xxxxxxxxxx`）。
- 不要在浏览器 DevTools 里长期勾选 “Update on reload” 后忘记取消；那会改变正常缓存行为。
- 缓存清理：应用设置里没有“清缓存”按钮；需要时在 DevTools → Application → Service Workers 注销，再刷新。**清缓存不会删除 IndexedDB 学习数据**，但任何清理操作前仍建议先导出备份。

## 5. 离线打不开

- 第一次必须联网打开一次，让 Service Worker 完成安装并缓存外壳。
- 离线只保证同源静态外壳；AI 请求、外部链接、从未缓存的文章不会离线可用。
- 若断网后显示“应用外壳尚未缓存”，联网打开一次再试。
- 检查浏览器是否禁用了 Service Worker（无痕/隐私模式可能限制）。

## 6. AI 请求失败

- 基础学习、复习、备份不依赖 AI；AI 是可选增强。
- 检查 Endpoint / Model / Key 是否配置；Key 只保存在当前浏览器本地（勾选记住时），备份不包含 Key。
- 离线、CORS、429、5xx、超时都会失败；应用会显示错误，不会把 AI 输出当作掌握证据。
- 不要为了“让按钮变绿”伪造 AI 结果。

## 7. 存储空间不足

- 浏览器可能清理未持久化的站点数据；设置 → 申请持久存储。
- 完整备份通常比原始数据库小/相近；D 数据集约 17.8 MB。
- 如果 `QuotaExceededError` 发生，当前阶段没有专门 UI 修复流程；先导出到文件，清理不必要浏览器数据，再重试。该路径未在本阶段自动化实测。

## 8. 两个标签页

应用故意用启动锁阻止第二个标签页同时写同一个数据库；第二个标签会显示“已在另一个窗口打开”。这是数据保护，不是 bug。关闭另一个标签页后刷新即可。
