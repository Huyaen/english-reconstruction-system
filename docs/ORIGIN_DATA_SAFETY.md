# 数据地址安全：localhost 与 127.0.0.1

**结论：本项目推荐且只支持固定使用 `http://localhost:4173` 作为日常学习地址。**
`http://127.0.0.1:4173` 可以打开同一个程序，但浏览器把它视为**另一个 origin**，学习数据在另一个 IndexedDB 空间里，不会自动共享、合并或迁移。

## 1. 为什么会这样

浏览器按 **scheme + host + port** 隔离存储：

| 地址 | 与推荐地址是否同一存储 |
| --- | --- |
| `http://localhost:4173` | 是，推荐 |
| `http://127.0.0.1:4173` | **否**（host 不同） |
| `http://localhost:4174` | **否**（port 不同） |
| `https://localhost:4173` | **否**（scheme 不同） |
| 另一个浏览器 / 另一个浏览器 profile | **否** |

代码无法从服务端知道用户真实数据在哪个 origin；本阶段没有读取、迁移或删除任何真实浏览器数据。

## 2. 启动时实际使用哪个地址

- `start-windows.bat` → `node server.mjs`，默认端口 `4173`，终端打印 `http://localhost:4173`。
- `npm run dev` 绑定 `127.0.0.1:4173`，只用于开发；它不是日常学习地址。
- `npm run start:test` 是 `dist-test` 的测试端口 `4174`，不是用户数据。
- 所有 Phase 3–14 浏览器验收使用独立 profile 的 Edge/CDP，不碰日常浏览器 profile。

## 3. 应用内的提示（Phase 14）

设置页新增「数据地址」面板：

- 显示当前 origin 与推荐 origin；
- 当两者不一致时，明确写出「不同地址的学习数据不会自动合并」；
- 提供「在推荐地址打开」链接，但**不会自动跳转**；
- 不提供「一键迁移」：迁移必须先导出备份，再由用户显式导入。

面板字段 `#origin-panel[data-origin-current][data-origin-canonical][data-origin-same]` 供验收读取。

## 4. 手动迁移步骤（用户主动执行）

1. 在**当前实际有数据的地址**打开应用。
2. 设置 → 备份与迁移 → **导出全部学习数据**，确认 JSON 文件已下载。
3. 打开推荐地址 `http://localhost:4173`。
4. 设置 → 导入备份 → 选择刚导出的文件；确认恢复前先看清词书/单词/记录数量。
5. 检查完整性与核心计数；保留原备份，不要立刻删除旧地址数据。
6. 如果导入失败或计数不对：**不要清空旧地址**，先保留备份并排查。

应用不会自动执行以上步骤，也不会在地址不一致时假装数据还在。

## 5. 验收证据

`scripts/phase14-smoke.mjs`：

- 在 `127.0.0.1:4173` 写入 origin 标记；
- 切到 `localhost:4173`，确认读不到该标记；
- 切回 `127.0.0.1:4173`，确认标记仍在；
- 设置页显示当前/推荐地址，且 URL 不会被自动改写。

本机验收结果：**11/11**（使用独立 `edge-p14` profile；未接触真实用户 profile）。
